# PRD — אתר ליצירת בדיחות באמצעות AI

## 1. רקע ומטרות

### א. מטרת המוצר
לאפשר לכל משתמש לקבל בדיחה בעברית בנושא לבחירתו, או בדיחה כללית, באמצעות אתר מותאם למובייל הניתן להתקנה כ־PWA.

### ב. תיאור הבעיה
משתמש המעוניין בבדיחה בנושא מסוים זקוק לדרך פשוטה ומהירה לקבל אותה, ללא הרשמה או חיפוש ידני.

### ג. תיאור הפתרון
מסך הכולל תיבת טקסט להזנת נושא, לחצן ליצירת בדיחה ואזור להצגת התוצאה. מודל AI של OpenAI מייצר את הבדיחה באמצעות פנייה מה־Backend בלבד. כאשר לא הוזן נושא, נוצרת בדיחה כללית.

## 2. קהלי יעד וצרכי משתמשים

### א. User Personas — פרסונות משתמשים
משתמשים מהקהל הרחב, כולל ילדים, המעוניינים בבדיחה בעברית בנושא לבחירתם או בבדיחה כללית, דרך ממשק פשוט המתאים גם לשימוש במובייל.

### ב. User Stories — סיפורי משתמש
- כמשתמש, אני רוצה להזין נושא ולקבל בדיחה עליו, כדי ליהנות מתוכן שמתאים לבחירתי.
- כמשתמש, אני רוצה לקבל בדיחה גם ללא הזנת נושא, כדי ליהנות ללא צורך לחשוב על נושא.
- כמשתמש, אני רוצה ללחוץ שוב ולקבל בדיחה חדשה לפי הנושא שבתיבה, כדי להמשיך ליהנות.
- כמשתמש, אני רוצה להשתמש באתר ללא הרשמה או התחברות, כדי להגיע מיד לפעולה המרכזית.
- כמשתמש במובייל, אני רוצה להתקין את האתר כ־PWA, כדי לגשת אליו בנוחות.

## 3. זרימות וחוויית משתמש

### א. User Journey — מסע המשתמש
המשתמש רוצה רגע של הומור, נכנס לאתר או פותח את ה־PWA, מזין נושא או משאיר את התיבה ריקה, לוחץ על לחצן היצירה ומקבל בדיחה בעברית. לאחר מכן הוא יכול לבקש בדיחה נוספת באותו נושא או לשנות את הנושא.

### ב. User Flows — זרימות המשתמש

#### יצירת בדיחה בנושא
1. המשתמש פותח את המסך הראשי.
2. המשתמש מזין נושא, לדוגמה: „חתולים”.
3. המשתמש לוחץ על לחצן יצירת הבדיחה.
4. מוצג „מכינים לך בדיחה…” והלחצן אינו זמין ללחיצות נוספות.
5. ה־Backend פונה למודל ה־AI ליצירת בדיחה בעברית בנושא.
6. הבדיחה מוצגת במסך והלחצן חוזר להיות זמין.

#### יצירת בדיחה כללית
אותה זרימה, ללא הזנת נושא. הבקשה נשלחת ליצירת בדיחה כללית בעברית.

#### יצירת בדיחה נוספת
לאחר הצגת תוצאה, לחיצה נוספת מפעילה בקשת יצירה חדשה לפי הנושא הקיים בתיבה באותו רגע. אם התיבה ריקה, נוצרת בדיחה כללית.

#### תקלה וניסיון נוסף
אם היצירה נכשלת, מוצג „לא הצלחנו ליצור בדיחה. נסו שוב”. הלחצן חוזר להיות זמין ומאפשר ניסיון נוסף.

### ג. UX Requirements — דרישות חוויית משתמש
- ממשק בעברית ובכיווניות RTL, מותאם למובייל.
- מסך ראשי פשוט המציג בבירור את תיבת הנושא, לחצן היצירה ואזור התוצאה.
- הזנת נושא היא פעולה אופציונלית ואינה תנאי לשימוש בלחצן.
- הבדיחות תמיד בעברית, גם אם הנושא נכתב בשפה אחרת.
- בזמן יצירה יוצג חיווי ההמתנה שאושר, ותימנע שליחה נוספת דרך הלחצן עד לסיום הבקשה.
- המוצר פונה לקהל הרחב, כולל ילדים; התוכן יהיה נקי ומתאים לקהל זה.
- אין צורך בהרשמה או בהתחברות.

**הנחת ניסוח בלבד:** מאחר שלא נקבעו נוסחי התיבה והלחצן, ישמשו „נושא לבדיחה (לא חובה)” ו־„צרו לי בדיחה”. ניתן לעדכן ניסוחים אלה בלי לשנות את ההתנהגות.

## 4. דרישות פונקציונליות

### א. Features & Functional Requirements — פיצ'רים ודרישות פונקציונליות

| מזהה | יכולת | דרישות וכללי פעולה |
|---|---|---|
| FR-01 | הזנת נושא | המסך יכלול תיבת טקסט להזנת נושא חופשי. אין חובה להזין ערך. |
| FR-02 | הפעלת יצירה | לחיצה על הלחצן תפעיל בקשת יצירה אחת לפי תוכן התיבה באותו רגע. פתיחת המסך כשלעצמה אינה מפעילה יצירה. |
| FR-03 | בדיחה בנושא | כשקיים נושא, מודל ה־AI יתבקש ליצור בדיחה עליו. לדוגמה, הזנת „חתולים” תוביל לבדיחה על חתולים, בכפוף לכללי התוכן. |
| FR-04 | בדיחה כללית | כאשר התיבה ריקה, מודל ה־AI יתבקש ליצור בדיחה כללית. |
| FR-05 | שפת התוצאה | כל בדיחה תוצג בעברית, ללא תלות בשפת הנושא שהוזן. |
| FR-06 | התאמת תוכן | בנושא שאינו מתאים לקהל הרחב תיווצר בדיחה נקייה המתייחסת לנושא, אם ניתן; אחרת תוצג בדיחה כללית נקייה. |
| FR-07 | תוצאה נוספת | לחיצה לאחר השלמת בקשה תפעיל יצירה חדשה לפי הנושא שבתיבה. אין התחייבות למניעת חזרות בין תוצאות. |
| FR-08 | מצב המתנה | במהלך הבקשה יוצג „מכינים לך בדיחה…”, והלחצן יושבת עד להצלחה או לכישלון. |
| FR-09 | תקלה | בכישלון תוצג ההודעה „לא הצלחנו ליצור בדיחה. נסו שוב”, ותתאפשר שליחה נוספת. |
| FR-10 | גישה פתוחה | האתר יהיה פתוח לשימוש ללא הרשמה וללא התחברות. |
| FR-11 | התקנת PWA | ניתן יהיה להתקין את האתר כ־PWA בסביבות התומכות בכך. יצירת בדיחות תדרוש חיבור לאינטרנט גם לאחר התקנה. |

### ב. Edge Cases & Error Handling — מקרי קצה וטיפול בשגיאות

| מקרה | התנהגות נדרשת |
|---|---|
| תיבה ריקה | יצירת בדיחה כללית; אין להציג שגיאת שדה חובה. |
| תיבה המכילה רווחים בלבד | **הנחה:** יש להתייחס אליה כתיבה ריקה וליצור בדיחה כללית. |
| נושא בשפה שאינה עברית | יצירת בדיחה בעברית על הנושא, בכפוף לכללי התוכן. |
| נושא שאינו מתאים לקהל הרחב | יצירת בדיחה נקייה בנושא אם אפשר; אחרת בדיחה כללית נקייה. |
| לחיצות חוזרות בזמן יצירה | הלחצן אינו זמין, ולכן אינו שולח בקשות נוספות במהלך ההמתנה. |
| אין אינטרנט, כשל תקשורת או כשל בשירות ה־AI | הצגת הודעת התקלה שאושרה והחזרת האפשרות לנסות שוב. אין יצירה מקומית ב־Offline. |
| לא התקבלה בדיחה להצגה | טיפול ככישלון יצירה באמצעות הודעת התקלה ואפשרות לניסיון נוסף. |

## 5. דרישות טכניות ואילוצים

### א. דרישות טכניות
- אתר Web מותאם למובייל.
- התקנה כ־PWA בסביבות התומכות בכך.
- שפת הממשק ושפת הבדיחות: עברית; כיווניות הממשק: RTL.
- המודל ליצירת הבדיחות: מודל של OpenAI שנתמך באופן שוטף ואינו מסומן Deprecated. זהות המודל תוגדר בהגדרת שרת אחת, כך שהחלפת מודל בעתיד לא תחייב שינוי קוד או שינוי מסמך זה. הבחירה הראשונית מתוארת ב־ARCHITECTURE.
- הגישה לשירות ה־AI תתבצע בצד ה־Backend בלבד.
- ה־API Key יישמר וישמש אך ורק ב־Backend; אין לכלול אותו בקוד ה־Frontend או לחשוף אותו בתשובות ללקוח.
- אין מסד נתונים באפליקציה.
- יצירת בדיחות מחייבת חיבור לאינטרנט.

### ב. אילוצים
- אין הרשמה, התחברות או חשבונות משתמשים.
- התוכן חייב להתאים לקהל הרחב, כולל ילדים, בהתאם לכללי התוכן בסעיף 4.
- אין בחירה במסמך זה של Frameworks, ספק Hosting או ארכיטקטורה מעבר לאילוצים שהוגדרו במפורש.
- לא הוגדרו תקציב, מכסת בקשות, זמני תגובה מספריים או רשימת דפדפנים וגרסאות מחייבת; אין במסמך התחייבות לערכים כאלה.

## 6. מה מחוץ לטווח — Out of Scope

- הרשמה, התחברות וניהול חשבונות.
- מסד נתונים.
- היסטוריית בדיחות, מועדפים ושמירת בדיחות בין ביקורים.
- יצירת בדיחות ב־Offline.
- ממשק או בדיחות בשפות נוספות.
- פנייה ישירה ל־AI מה־Frontend או שמירת API Key בו.
- יכולות נוספות מעבר להזנת נושא, יצירת בדיחה והצגתה, מצבי המתנה ותקלה והתקנה כ־PWA.
