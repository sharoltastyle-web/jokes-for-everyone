# MILESTONES — בדיחה לכל

מסמך זה מתרגם את PRD.md, ARCHITECTURE.md ו־DESIGN.md לשלוש אבני דרך לפיתוח. כל אבן דרך כוללת יכולת ניתנת להפעלה ולבדיקה, עם Frontend ו־Backend משולבים ככל שנדרש.

## מסגרת ותלויות

| Milestone | תוצר מרכזי | תלות |
|---|---|---|
| 1 | יצירת בדיחה בעברית מקצה לקצה בממשק המעוצב | גישת פיתוח ל־OpenAI ול־GitHub |
| 2 | בדיקת תוכן, שימוש חוזר אמין, טיפול בתקלות והשלמת הגנות | השלמה ואישור של Milestone 1 |
| 3 | אתר ציבורי ו־PWA עם Deployment אוטומטי | השלמה ואישור של Milestone 2 וגישה ל־Vercel |

- שם המוצר המאושר הוא **„בדיחה לכל”**, וכך גם ב־Manifest. הכותרת במסך נותרת „יצירת בדיחה”, לפי DESIGN.
- אין Database, Authentication, אחסון היסטוריה או Database Migrations. ההנחיות להקמת שני מסדי נתונים אינן חלות על הפרויקט.
- הפיתוח יתבצע ב־Next.js, TypeScript ו־Node.js בהתאם לארכיטקטורה, ללא הוספת שירותים או מסכים.
- מודל ה־AI נבחר בתחילת Milestone 1 לפי הכללים ב־ARCHITECTURE (לא GPT-5, שיוסר ב־11 בדצמבר 2026), מוצג למשתמש לאישור ומתועד כ־ADR. החלפת מודל לאחר מכן מחייבת אישור משתמש, אך אינה מחייבת עדכון PRD. בדיקות עם Mock אינן נחשבות להוכחת אינטגרציה חיה.
- סודות יוגדרו בהדרכה פשוטה של המשתמש, ישירות בסביבה המתאימה; אין לבקש להדביק API Key בשיחה.

## Milestone 1 — יצירת בדיחה בממשק המעוצב ✅

### שם ומטרה

לאפשר למשתמש להזין נושא, או להשאיר את התיבה ריקה, ולקבל בדיחה בעברית דרך המערכת המלאה.

### מה יש לממש

- הקמת Repository ב־GitHub ופרויקט אחד עם גרסאות נעולות, פקודות Build ובדיקות TypeScript ו־Lint.
- סביבת Development עם מפתח פיתוח ב־Backend בלבד, ותצורת שרת לפי ARCHITECTURE.
- המסך היחיד „יצירת בדיחה”: כותרת, Label „נושא לבדיחה (לא חובה)”, תיבה, לחצן „צרו לי בדיחה” וכרטיס תוצאה.
- יישום צבעים, Heebo, RTL, מידות וריווח לפי DESIGN וה־Mockup; ללא מסגרת מכשיר או כותרת לוח חיצונית.
- בחירת מודל ה־AI לפי ARCHITECTURE, אישור המשתמש ותיעוד כ־ADR, לפני החיבור החי.
- POST /api/joke וחיבור Responses API למודל שב־OPENAI_MODEL באמצעות ה־SDK הרשמי, ללא היסטוריית שיחה ועם store: false.
- יצירה לפי הנושא או יצירה כללית לאחר trim של ערך ריק; התוצאה תמיד בעברית.
- הוראות יצירה לתוכן נקי המתאים גם לילדים. (בדיקת Moderation וה־fallback נבנים ב־Milestone 2; ב־Milestone 1 האתר רץ רק מקומית ואינו ציבורי.)
- מצבי המסך לפי DESIGN: המתנה עם „מכינים לך בדיחה…” בכרטיס ולחצן Disabled, מניעת שליחה כפולה, הודעת תקלה רגילה וחזרה לאפשרות שליחה.

### תוצר מצופה

אפליקציה עובדת ב־Development: המשתמש פותח את המסך, מבקש בדיחה וקורא את התוצאה בממשק המעוצב, ללא הרשמה.

### Definition of Done

- [ ] המודל נבחר, אושר על ידי המשתמש ותועד כ־ADR; הוא אינו מופיע בדף Deprecations של OpenAI.
- [ ] הזנת „חתולים” ושליחה מחזירות בדיחה בעברית הקשורה לנושא; בדיקה חיה מתועדת עם המודל שנבחר מצליחה.
- [ ] תיבה ריקה ותיבה המכילה רווחים בלבד מפעילות יצירה כללית, ללא שגיאת שדה חובה.
- [ ] נושא בשפה אחרת מחזיר בדיחה בעברית בבדיקת אינטגרציה מדגמית.
- [ ] פתיחת המסך אינה שולחת בקשת AI ואינה מציגה מראש את בדיחת הדוגמה מה־Mockup.
- [ ] בלחיצות מהירות בזמן המתנה נשלחת בקשה אחת בלבד; לאחר סיום הלחצן זמין שוב.
- [ ] מצבי המסך (פתיחה, המתנה, הצלחה, תקלה) תואמים לטבלת המצבים ב־DESIGN.
- [ ] כשל יצירה מציג „לא הצלחנו ליצור בדיחה. נסו שוב”, וניסיון נוסף יכול להצליח.
- [ ] המסך תואם חזותית ל־DESIGN: עמודה אחת, צבעים וטיפוגרפיה נכונים ותוכן מיושר בהתאם ל־RTL.
- [ ] בקשות הדפדפן עוברות רק ל־API המקומי; אין API Key בקוד Client, ב־Bundle, ב־Git או בתשובות.
- [ ] Build, TypeScript ו־Lint עוברים; קוד המקור נשמר ב־GitHub ללא סודות.

## Milestone 2 — בדיקת תוכן, שימוש חוזר אמין והשלמת ההגנות ✅

### שם ומטרה

לוודא שהתוכן המוצג מתאים לקהל הרחב, ולאפשר רצף שימוש מלא גם בתוכן משתנה ובתקלות, תוך שמירה על קריאות, פרטיות וגבולות הבקשות.

### מה יש לממש

- בדיקת Moderation לפלט ו־fallback יחיד לבדיחה כללית במקרים שהוגדרו בארכיטקטורה. אין לחשוף פלט לפני הבדיקה.
- בדיקה ידנית של תוצאות על רשימה קבועה של לפחות 8 נושאים רגישים (למשל: מוות, מלחמה, אלכוהול, דת, גוף האדם, מחלות, פוליטיקאי, קללה), וחיזוק הוראות היצירה לפי הצורך.
- בקשות חוזרות לפי ערך התיבה בזמן הלחיצה, החלפת הבדיחה הקודמת ושינוי נושא באותו מסך.
- השלמת אימות הקלט, מגבלת גוף הבקשה, חוזה השגיאות ו־no-store לפי ARCHITECTURE.
- תקציב הזמן הכולל, Timeouts והגדרת maxRetries: 0; ה־fallback היחיד כפוף לאותו תקציב.
- מיפוי כשלי רשת, ספק ותשתית להודעת התקלה המאושרת, לרבות תשובות שאינן JSON.
- הגנות Origin ו־HTTP, פלט כטקסט רגיל, כותרות אבטחה ו־Logs ללא תוכן משתמש או סודות.
- Label נגיש, חיווי aria-live, מיקוד מקלדת, Focus ו־Disabled לפי השפה העיצובית.
- התאמה למסך צר, למקלדת מובייל ולבדיחה ארוכה ללא חיתוך טקסט.

### תוצר מצופה

גרסת Development מלאה ועמידה לבדיקת המשתמש: ניתן לבקש בדיחות ברצף, לשנות נושא, להיתקל בתקלה ולנסות שוב, ללא מעבר למסך נוסף.

### Definition of Done

- [ ] בדיקות עם Mock מאמתות שפלט שנפסל אינו מוצג, מופעל fallback אחד לכל היותר, וכשל Moderation אינו חושף פלט.
- [ ] רשימת הנושאים הרגישים נבדקה ידנית מול המודל החי; כל התוצאות נקיות ומתאימות לילדים, והתוצאות מתועדות למשתמש.
- [ ] שתי שליחות עוקבות מפעילות שתי בקשות נפרדות; הבדיחה האחרונה מחליפה את הקודמת. אין מבחן המחייב שכל תוצאה תהיה ייחודית.
- [ ] שינוי נושא משפיע על הבקשה הבאה, וריקון התיבה מחזיר למסלול של בדיחה כללית.
- [ ] בדיקות Mock מכסות Timeout, תשובה ריקה, incomplete, refusal, כשל ספק וכשל בבדיקת תוכן, לפי כללי ה־fallback שבארכיטקטורה.
- [ ] ניתוק רשת ותשובת שגיאה שאינה JSON מחזירים את הלחצן לפעולה ומציגים את ההודעה המאושרת.
- [ ] חוזה ה־API נבדק עבור JSON פגום, טיפוס topic שגוי, גוף גדול מדי, שיטת HTTP ו־Content-Type לא נתמכים ו־Origin אסור.
- [ ] גבולות הזמן והפלט תואמים לארכיטקטורה; אין Retry אוטומטי נוסף ליצירה.
- [ ] פלט דמוי HTML מוצג כטקסט ואינו מתבצע; Responses מסומנות no-store.
- [ ] Logs אינם מכילים נושא, בדיחה, Prompt או API Key; לא נוספה שמירת נתונים בדפדפן.
- [ ] בדיקה במובייל ובמקלדת מאמתת סדר רכיבים תקין, Focus נראה, קריאות ותוצאה ארוכה ללא חיתוך או גלילה אופקית.
- [ ] כותרות האבטחה שהוגדרו ב־ARCHITECTURE קיימות גם בהרצת Build של Production, וכל בדיקות Milestone 1 ממשיכות לעבור.

## Milestone 3 — אתר ציבורי ו־PWA עם פריסה אוטומטית ✅

### שם ומטרה

להנגיש את המוצר באינטרנט ולהתקנה כ־PWA, עם הפרדת סודות ופריסה אוטומטית מ־GitHub.

### מה יש לממש

- חיבור ה־Repository ל־Vercel והגדרת Preview מענפי עבודה ו־Production מענף main.
- הגדרת מפתח OpenAI אחד לכל הסביבות (Development, Preview ו־Production), לפי ADR-8.
- הגדרת OPENAI_MODEL, APP_ORIGIN, Node.js, Fluid Compute ו־maxDuration לפי ARCHITECTURE.
- Pipeline הכולל npm ci, בדיקות TypeScript ו־Lint ו־next build, ללא קריאות AI חיות בזמן Build.
- Manifest בשם „בדיחה לכל”, עברית ו־RTL, start_url, standalone, אייקונים במידות המוגדרות ו־apple-touch-icon.
- HTTPS, גישה ציבורית ללא התחברות, כלל WAF Rate Limiting על ה־API והתראות שימוש לפי ARCHITECTURE.
- בדיקת תוכנית Hosting לפי אופי השימוש והגדרת תצורות השירות בהדרכה צעד אחר צעד כאשר נדרשת פעולת המשתמש.
- אימות התקנה והפעלה דרך מנגנוני הדפדפן, ללא תוספת מסך התקנה, Service Worker או יצירה ב־Offline.

### תוצר מצופה

כתובת Production פעילה של „בדיחה לכל”, הפועלת בדפדפן וב־PWA מותקן בסביבה תומכת, עם פריסה אוטומטית של עדכונים מאושרים.

### Definition of Done

- [ ] Push לענף עבודה יוצר Preview; עדכון main יוצר Deployment אוטומטי לאחר מעבר כל בדיקות ה־Build.
- [ ] לא ממזגים ל־main במהלך אבני הדרך הקודמות באופן שיפרס גרסה ציבורית חלקית; ה־Production Deployment מבוצע במסגרת אבן דרך זו.
- [ ] ב־Production ניתן ליצור בדיחה אמיתית עם נושא ובלעדיו באמצעות המודל שנבחר, ללא הרשמה או הגנת כניסה.
- [ ] ב־Preview יצירת בדיחה עובדת (בדיקת ה־Origin מאשרת את כתובת ה־Preview), ובקשה מ־Origin זר נדחית.
- [ ] המפתח אינו נגיש ב־Repository, ב־Bundle או בדפדפן, ומוגדר ב־Vercel כ־Sensitive; לאחר שינוי תצורה בוצע Deployment שמחיל אותה.
- [ ] ה־Manifest תקין ושמו „בדיחה לכל”; אייקונים ו־HTTPS זמינים, והאפליקציה נפתחת בהתקנה תומכת במצב standalone.
- [ ] נבדקה התקנה ב־Chrome על Android והוספה למסך הבית ב־Safari על iOS, ככל שסביבות בדיקה אלה זמינות. בדיקה שלא בוצעה מסומנת כחסרה ואינה מדווחת כהצלחה.
- [ ] האתר עובד גם ללא התקנה; ניסיון יצירה ללא חיבור לאחר טעינה מציג את הודעת התקלה הרגילה. אין דרישה לפתיחה קרה ב־Offline.
- [ ] כלל WAF פעיל ונבדק מול הסף שהוגדר; תשובת הגבלה אינה שוברת את המסך ואינה חושפת פרטי ספק.
- [ ] תוכנית Vercel מתאימה לשימוש, והתראות שימוש מוגדרות; לא מוצגת התראה כתחליף לתקרת חיוב קשיחה.
- [ ] נבדקו אבטחה, RTL והתנהגות מלאה בגרסה הפרוסה; קיים תיעוד של Deployment תקין שאליו ניתן לבצע Rollback ושל התצורה הנדרשת לו.
- [ ] כל בדיקות אבני הדרך הקודמות עוברות; כל חסימה או בדיקה שלא הושלמה מפורטת לפני בקשת אישור ההשלמה.

## Development Execution Rules — הנחיות ל־AI המפתח

1. **יש לפתח לפי הסדר:** Milestone 1, לאחריו Milestone 2, ולאחריו Milestone 3.
2. **בסיום כל Milestone יש לעצור את הפיתוח.** יש להציג למשתמש את התוצר העובד, דרך לצפות בו או לבדוק אותו, ותוצאות בדיקה מול כל סעיף ב־Definition of Done.
3. לכל תנאי יש לציין עבר / נכשל / לא נבדק, עם ראיה קצרה מתאימה. יש להבחין בין בדיקה עם Mock לבין בדיקת אינטגרציה חיה.
4. **אין להתחיל בפיתוח ה־Milestone הבא ללא אישור מפורש של המשתמש.** שתיקה, חלוף זמן או הצלחת בדיקות אינם אישור.
5. כאשר תנאי אינו מתקיים, יש לתקן ולבדוק במסגרת ה־Milestone הנוכחי. אין לדווח על השלמה או להעביר פערים לשלב הבא ללא החלטה מפורשת של המשתמש.
6. אין להוסיף מסכים, שירותים או דרישות מעבר למסמכי הפרויקט. אי־זמינות המודל שנבחר או סתירה מהותית במקורות מחייבות הצגת הבעיה למשתמש, ללא החלפת מודל או שינוי מוצר באופן עצמאי.
7. אישור אבן דרך אינו פוטר מבדיקות Regression בהמשך. כל שינוי שמתפרסם לאחר הפריסה חייב לעבור את בדיקותיו לפני עדכון ענף Production.
